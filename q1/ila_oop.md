# ILA 3-1: Applying the Four Pillars of OOP

## Sari-Sari Store Inventory System

### 1. Encapsulation
Encapsulation is a powerful tool in hiding internal, complex data from the outside world by combining them into a "class" or single unit. It plays an important role in data safety and changing code without having to break other codes. In the sari-sari inventory, we can combine product details (such as product name, price, and stock quantity) to put them into one parent class. 

### 2. Abstraction
Similar to encapsulation, abstraction makes sure to turn complex words into simpler terms. In the sari-sari inventory problem, a cashier can check out items with their quantities and ids. All the messy and complex calculations involved in stocks and the inventory can be hidden using this pillar.

### 3. Inheritance
Inheritance is a pillar of OOP that passes down the code properties of a parent class to a new class. This allows programmers to reuse code and organize code structures. In the problem, a main Product class can be created to include child classes like PerishableProduct (adds expiration dates).

### 4. Polymorphism
As the name suggests, polymorphism means "many forms". Basically, a single name or class can mean different things, and those objects can be called in unique methods to reuse code and save time. In the problem, a shared function name like get_product_price() can be used to determine the total price of all items inside the main class.

## Reflection
Out of the four pillars of Object-Oriented Programming, I think encapsulation would be the best for improving the sari-sari store inventory system. It prevents the loss of inventory items, allows easier debugging, guarantees that the store rules run smoothly, and protects internal inventory data.
